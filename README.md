# Desktop Rider

一个用来验证桌面 DIY 体验的中文交互原型。无构建步骤；人物分割使用项目内固定版本的 MediaPipe JS / WASM 与模型，无需 npm 安装或运行时联网；所有壁纸、设置与方案均在本地处理。

## 启动

在本目录执行：

```sh
python3 tools/serve.py
```

打开 http://127.0.0.1:4173 。服务仅监听本机回环地址。也可以使用 `npm start`。

## 已实现

- 完整、垂直、斜切三种桌面布局。
- 分裂角度 −80° 至 80°、横纵控制点 1% 至 99%、间距 0 至 60px，以及间隙颜色。实际左右区域面积单独显示。「分割线形状」可把直线弯成弧形（−60 至 60）或叠加 1–6 个波浪并调幅度，手柄仍控制基准线；预览的 clip-path、导出的画布裁切与客户端的播放方案用同一组采样点。
- 分区画面：每块分区可以换成自己的图片（最长边 1600px），并单独平移、缩放；在预览里直接拖动某块画面即可平移，滚轮缩放；「用共享壁纸」改回。人物识别、悬浮抠图始终基于共享壁纸。默认「不露白」：画面不会小于分区、也拖不出分区；关掉后露出的空白按「露白填充」处理——模糊延展（同图放大模糊铺底）、镜像延展（翻转接续）、本机扩图（用现有 PatchMatch 补全器从图片自身纹理把空白补上，停下 0.35 s 后在 Worker 里计算一次并缓存，预览与导出共用）或间隙色。
- 点击「在画面上选分割位置」自由落点；控制点支持二维拖动，两端可拖动调整角度。方向键微调，Shift 加速。
- 普通模式可独立设置原图切分点（5%–95%）。壁纸先按桌面比例裁切，再拆成左右两部分；开启联动后，每部分等比铺满自己的分区，随分区大小、斜切角度和间距重新定位与缩放。关闭联动时保持整张壁纸固定，只移动裁切边界。预览、模板缩略图与导出共用同一套图像映射。
- 人物优先：本机识别人像，人物沿用统一取景并随控制点整体平移，分割缝经过人物后方。联动时预留 18% 取景余量，边缘会适量裁切。背景位移配合保护带羽化，避免将人物分别缩放或出现重复轮廓。支持识别状态和失败重试。
- 人物悬浮：在本机识别画面主体并抠出为独立图层，可在预览中直接拖动、滚轮缩放、方向键微调，支持水平翻转、投影，以及「保留原位人物」（人物留在原处，悬浮的是副本，不补全背景）；同一人物可复制多份（最多 12 份），每份单独拖动、缩放、翻转，点击画面中的某一份或按面板里的序号即可选中（被挡住的那份也能选到；选中后在它露出或被遮住的实体部分拖动都只移动它，点击透明边角会落到下面那份），选中框始终画在所有副本之上，四角拖动缩放、上方圆点拖动旋转（Shift 吸附 15°），可上移 / 下移图层顺序或删除；每份还有自己的旋转、不透明度、色相、饱和度、亮度与发光（颜色可选），预览用 CSS 变换与滤镜、导出用 canvas 同样的变换与滤镜画出，复制一份时外观一起带走；原位置用画面其余部分的真实纹理补全背景（多尺度 PatchMatch，在 Worker 中运行，2000px 图约 2–4 秒）。自动识别使用人像模型找到起点，再用 MediaPipe MagicTouch 点选模型生成轮廓，并以画面亮度为引导做导向滤波（guided filter）把边缘贴回真实轮廓，发丝、衣褶能保留；插画、线稿同样可用；「调整抠图范围」中点击添加、右键或切换「去除」后点击减去。抠图点、位置、大小随方案保存，导出 PNG 时人物绘制在悬浮位置。
- 从 Wallpaper Engine 导入：选择创意工坊 431960 文件夹（或单个壁纸），列出全部壁纸。场景壁纸在本机解析 scene.pkg：有多个图片图层时默认给出按 scene.json 位置叠好的「合成画面」，也可以单独取某个图层（PNG / JPEG / 原始 RGBA / LZ4 / DXT，原始分辨率）；视频壁纸拖动滑块选一帧；网页壁纸及其他类型使用预览图。导入后与本地图片一样参与分裂、人物优先与人物悬浮。
- 4 张项目内原创 SVG 山景壁纸、1 张人像实拍壁纸与 4 套布局；导入 JPG / PNG / WebP，最高 20 MB，导入后最长边缩至 2000px。
- 16:10、16:9、4:3 比例与 100% 至 160% 壁纸缩放，支持横、纵取景调整。
- 最多 3 个收纳分区、每区 6 个示例快捷项；支持拖入分区、点击或 Enter 移至下一区、按类型整理。拖动分区标题可把分区放到桌面任意位置（方向键微调），位置随方案保存，「桌面管理」里可一键回到默认位置。
- 方案命名、保存、恢复、删除；自动保存工作草稿，刷新前同步待保存修改。
- 导出 1600px 宽 PNG 分裂壁纸，16:10 时为 1600×1000。只导出壁纸，不含示例图标、分割手柄与界面。
- 「隐藏桌面，只看壁纸」：页脚按钮、点一下任意分区标题或双击空白壁纸，分区、Dock、顶栏、问候语、壁纸名一起飞出画面（顶栏向上、Dock 向下、分区飞向各自较近的边），只留壁纸与悬浮人物；像 macOS 一样点一下壁纸就全部回来。
- 全屏预览、窄屏布局、键盘焦点、减少动态效果偏好。
- 模块机制（`core.js`）：桌面歌词、文件管理、时钟这类后续功能各写成 `modules/` 下的一个文件，通过 `Rider.register` 接入自己的状态切片（随草稿、方案、重置一起处理）、侧栏视图、设置面板、桌面图层和导出绘制；模块出错只记录日志，不影响核心。`modules/note.js`「桌面文字」是示例：一行文字可拖动、缩放、换色，随方案保存并画进导出 PNG。接口说明见 `docs/modules.md`。
- 图层（`modules/layers.js`）：在分裂壁纸之上自由叠放图片、视频与形状（矩形 / 椭圆，纯色或渐变），最多 24 层。每层可在预览里拖动、滚轮缩放、四角等比缩放、边中点改宽高、圆点旋转，方向键微调、Delete 删除；右侧面板有图层列表（显示 / 隐藏、锁定、上下移、复制、删除）与属性：位置、宽高、旋转、不透明度、模糊、色相、饱和度、亮度、圆角、水平翻转、填充方式、混合模式（正片叠底、滤色、叠加、柔光、变亮、变暗、差值），以及放在人物之下还是之上。图片存进方案（最长边 1600px），视频存本浏览器 IndexedDB；导出 PNG 时按同样的变换、滤镜与混合模式绘制（视频取当前帧）。 Windows 客户端会把未隐藏的视频图层连同位置、变换、滤镜与混合模式交给桌面层窗口逐帧播放（人物之下或之上都可以，最多 6 个）。 桌面层视频有节能策略：桌面被全屏 / 最大化窗口遮住或用电池时暂停（客户端面板与托盘里的「节能暂停」可关），锁屏、休眠始终暂停，恢复后继续；层窗口只在视频出新帧时重绘。
- 桌面歌词（`modules/lyrics.js` + 共享渲染器 `lyrics-view.js` / `lyrics-view.css`）：在 Windows 客户端里跟随系统「正在播放」的歌曲（QQ音乐、网易云音乐等任何向 Windows 媒体控件报告曲目的播放器）自动显示歌词。歌词从 QQ音乐（逐字 QRC，客户端本地解密）或网易云音乐（逐行 + 翻译）的公开接口按歌名、歌手匹配获取，可指定歌词站、指定歌曲或手动粘贴 LRC / QRC / YRC。三种显示方式：卡拉 OK 逐字点亮（按字时间用高亮色填充，无逐字数据的歌词按整句时长线性点亮，当前字可发光）、多行舞台（3 / 5 行，当前句放大，邻句缩小、变暗、逐级模糊，带回弹的滑动）、单句切换；切换方式有淡入淡出、上滑、模糊聚焦、逐字浮现、直接切换，时长可调。字体（内置或任意已安装字体名）、字重、大小、文字色、点亮色、发光、描边、投影、磨砂底衬、对齐、歌词区宽度与位置（预览里拖动）、下一句预告、翻译、间奏超过 5 秒时的三点呼吸进度都可自定义；预览用带字时间的示例歌词循环播放，导出 PNG 画当前句（含已点亮部分）。 只有打开「桌面歌词」视图时歌词框才响应鼠标，此时它浮在人物副本、图层、分区、Dock 之上且其他浮层穿透，不会误点；离开该视图后歌词穿透鼠标。
- 动态壁纸（`modules/live.js`）：导入 MP4 / WebM 视频（最大 500 MB），或在 Wallpaper Engine 导入里选视频壁纸；取一帧作为静态壁纸，照常参与分裂、人物识别、人物悬浮与 PNG 导出，预览里视频则在两块分区上实时播放，裁切与定位与静帧完全一致。可切换播放 / 静帧、重新取帧；「减少动态效果」或人物优先模式下自动退回静帧。逐帧人物提取：人物悬浮时，视频帧在 Worker 里经同一人像模型（VIDEO 模式，每帧约 10–80 ms）得到蒙版，悬浮副本显示视频里正在动的人物（蒙版与它所属的那一帧对齐合成，帧间做时间平滑，可照常拖动、缩放、翻转、复制）；原位的遮盖来自一张持续学习的「干净背景板」：初始为静帧补全结果，之后凡是当前帧里没有人物的地方都在向实时画面靠拢（指数平均，人物周围留出宽余量），所以人物身后的流云、水面、光影照常运动，只有人物从未离开过的地面保持补全结果；「保留原位人物」时只让副本动、不遮盖；面板里可以关闭逐帧提取。视频保存在本浏览器的 IndexedDB，方案只记录开关与取帧位置。在 Windows 客户端里应用后，桌面层窗口按同一几何实时播放视频（间隙颜色一起画出，悬浮人物与桌面文字叠在其上），系统壁纸设为静帧作为客户端未运行时的兜底。

## 当前边界

这是浏览器交互原型，并不是已经接管操作系统桌面的应用。

- 收纳分区展示的是示例快捷项，不会移动、删除或打开真实文件。
- 导出的 PNG 可以由用户在系统设置中设为壁纸；本原型不会直接改动系统壁纸。
- 数据保存在当前浏览器、当前来源的 localStorage 中，没有账户和云同步。更换端口、浏览器或清除站点数据会失去这些方案；请导出重要壁纸。
- 用户壁纸作为压缩图片存入方案，浏览器存储容量有限。空间不足时会提示，不会假装保存成功。
- 人物悬浮的背景补全是基于样例的纹理复制，不是 AI 修补：草地、地板、墙纸、天空这类重复纹理能接得自然，补全时优先取同一水平带内的纹理（天空、树木、水面、地板通常上下分层），所以地平线、岸边、地板边缘能大致接上；但它不理解画面结构，被挡住的物体轮廓、透视线不会被「推理」出来，复杂插画中偶尔会复制出其他位置的局部物件，人物外沿的过渡带仍可能隐约看出形状。
- 已评估并放弃的方案：浏览器端 MI-GAN（28 MB ONNX）补全在小洞上能接出岸线，但在插画和大面积人物上会凭空生成柱子、墙面，整体不如现有方法；SlimSAM 点选分割（40 MB）对单点只取局部、多点仍漏掉头部，不比 MagicTouch 稳定。两者都没有进入仓库。
- 自动找人用的是人像分割模型，只认实拍或接近实拍的人物：插画、背影、线稿常常自动找不到，此时会直接打开「选择要悬浮的人物」，点一下人物即可，后续效果与自动识别相同。识别面积不足画面 1% 时同样视为没找到，避免把荷叶、拱门这类小块误当成人。人物悬浮只存在于预览和导出图中，不会成为系统桌面上的独立窗口。
- Wallpaper Engine 场景的「合成画面」只按位置、缩放、旋转和透明度把图片图层静态叠起来，不还原粒子、着色器特效、文字、脚本与音频；只有一个图片图层的场景直接给出该图层。支持内嵌 PNG / JPEG、原始 RGBA（含 LZ4）与 DXT1 / DXT3 / DXT5 纹理，RG88 / R8 这类遮罩通道会跳过。导入的画面压缩到最长边 2000px 存入浏览器。
- 动态壁纸的预览与桌面播放是把视频按分区几何裁切后原样播放：导出的 PNG 仍是静帧；人物优先模式无法作用于运动画面。逐帧人物提取只认实拍人物（插画、线稿的视频不会被逐帧提取，只能静帧悬浮），人物始终站着的那块地面只能用静帧补全结果，不会跟着视频动；蒙版漏检时背景板可能短暂学进人物的一点颜色，随后会被后续帧修正；人物走出「静帧人物框再向四周扩一半」的范围会被裁掉。目前只在网页预览里实现，Windows 客户端桌面层仍播放原视频加静态副本。视频不进方案，换浏览器或清除站点数据后需要重新导入。
- 多显示器壁纸、开机启动由 Windows 客户端提供（见下）；网页原型本身仍是单画面预览。系统窗口吸附与桌面图标接管尚未实现。

## Windows 客户端

`client/windows/` 是 Electron 客户端（先适配 Windows 11，Windows 10 待实测），把网页原样装进去并加上系统能力：按每台显示器真实分辨率渲染并设为系统壁纸（`IDesktopWallpaper`，多显示器分别设置）；悬浮人物与桌面文字渲染成透明 PNG，由点击穿透的桌面层窗口显示在壁纸之上、图标之下（WorkerW / Progman 挂载）；动态壁纸时同一个桌面层窗口按分区几何实时播放视频，再叠上述透明层；托盘运行、开机启动并恢复桌面层。网页侧通过 `modules/client.js` 接入，只有在客户端内（存在 `window.desktopRider`）才出现「应用到桌面」视图。运行与打包、结构与边界见 `client/windows/README.md`。本仓库在 macOS 上开发；系统相关部分由 GitHub Actions 的 "Windows client" 工作流在真实 Windows 上验证（`windows-2025` 为 Windows 11 24H2 内核、`windows-2022` 为 Windows 10 内核），已确认按显示器设壁纸、桌面层挂到 WorkerW / Progman 之下并铺满显示器、重启恢复与清理，并产出 x64 安装包。托盘与开机启动的实际交互仍建议在 Win11 真机过一遍。

真实文件整理仍未实现，应优先使用快捷方式并保留可撤销记录。

## 文件

- `index.html`：页面结构、控件与弹窗。
- `styles.css`：工作台样式与响应式布局。
- `core.js`：模块注册表、状态切片校验、事件与模块私有存储。
- `modules/note.js`：示例模块「桌面文字」，也是新模块的模板。
- `modules/live.js`：动态壁纸模块（视频导入、静帧捕获、分区画布播放、逐帧人物提取、给客户端的播放方案）。
- `modules/layers.js`：图层模块（图片 / 视频 / 形状，变换、滤镜、混合模式，图层列表与选中框手柄；`layers-top` 伴随注册负责人物之上的部分）。
- `modules/client.js`：Windows 客户端内的「应用到桌面」模块（仅在客户端中注册）。
- `client/windows/`：Electron 客户端（主进程、预加载桥、PowerShell 原生桥、桌面层页面、测试）。
- `app.js`：裁切几何、壁纸渲染、交互、导入导出、本地存储；启动时挂载模块并提供 `Rider.api`。
- `portrait.js`：人物保护、距离场、背景合成；预览与导出共用。
- `person-worker.js`：在 Worker 中运行本地人物分割模型。
- `cutout.js`：人物悬浮的点选蒙版合并、导向滤波边缘细化、透明人物图层与背景补全。
- `inpaint-worker.js`：在 Worker 中做基于样例的背景补全（多尺度 PatchMatch + 加权投票）。
- `wallpaper-engine.js`：读取 Wallpaper Engine 文件夹、解析 scene.pkg / .tex 纹理。
- `assets/`：内置壁纸及本地人物分割模型。
- `vendor/mediapipe/`：固定版本运行库与许可证。
- `docs/portrait-algorithms.md`：算法调研、选型、具体实现与限制。
- `docs/modules.md`：模块接口、生命周期、导出顺序，以及桌面歌词、文件管理等功能的落点。
- `tools/create_wallpapers.py`：生成项目内矢量壁纸。
- `tools/serve.py`：仅本机可访问的开发服务器。
- `tools/verify.cjs`：浏览器行为与导出验证，依赖当前开发环境的 Playwright 和 Chrome。
- `artifacts/desktop-design.png`、`artifacts/mobile-design.png`：验证时的页面截图。

## 已验证

执行 `node --check app.js` 与 `node tools/verify.cjs`。浏览器验证涵盖分裂设置、鼠标拖动、键盘调整、联动开关、导出间隙像素、模板、分区、方案保存/恢复/删除、图片导入后立即刷新、PNG 下载、390px / 1024px 页面宽度以及帮助弹窗。浏览器运行期间无未捕获错误。

壁纸联动专项回归：`node tools/verify-wallpaper.cjs`。使用坐标编码图片检查左右画面随比例变化、关闭联动后保持固定、零间距等分时还原原图；覆盖 24 种极端布局无露底，并比较浏览器预览与 PNG 导出中的采样像素。联动开关对比截图保存在 `artifacts/wallpaper-linked.png` 和 `artifacts/wallpaper-unlinked.png`。

人像测试壁纸「林间人像」的摄影来源和裁切说明见 `assets/CREDITS.md`。开启「人物优先」后，40° 斜切仍保持所识别人物的原始比例；发丝、透明边缘等效果受模型精度影响。此模式让缝隙从人物后方经过，并非让人物任意迁移或自动补全背景。

人物与分割交互回归：`node tools/verify-portrait.cjs`。普通模式和人物模式的测试与限制详见 `docs/portrait-algorithms.md`。

人物悬浮与 Wallpaper Engine 导入回归：`node tools/verify-float.cjs`。覆盖自动抠图、背景补全、拖动 / 滚轮 / 键盘、导出位置、刷新恢复、点选添加 / 去除，以及用测试生成的 scene.pkg（内嵌 PNG、LZ4 原始 RGBA 与 DXT5 纹理，另含 DXT1 四色 / 三色块的逐像素校验）验证文件夹扫描和图层解码。

客户端模块回归：`node tools/verify-client.cjs`，用假的 `window.desktopRider` 验证显示器列表、按显示器分辨率渲染、背景 / 叠加层拆分与导出逐像素一致、设置与桌面层清理。客户端自身：`cd client/windows && npm test && npm run smoke`；Windows 上再跑 `node test/windows.cjs`（真调用桥脚本并回查系统）。没有 Windows 机器时由 GitHub Actions 的 "Windows client" 工作流（`.github/workflows/windows.yml`）在 `windows-2025` / `windows-2022` 运行器上完成这三项并上传桌面截图与 x64 安装包。 真机清单：`client/windows/REAL-DEVICE-TEST.md`。

自由画布回归：`node tools/verify-canvas.cjs`，用纯色分区图检查弧形分割线把凸出处交给左侧、波浪与恢复直线，不露白限制（拖动只能向有画面的方向、滚轮缩不到分区以下、重新开启后回弹）与四种露白填充在预览画布和导出像素上的表现（含本机扩图完成后左上为红色纹理），分区换图 / 偏移 / 缩放在面板、拖动、滚轮与草稿中的表现，人物副本的旋转 / 色相 / 发光 / 不透明度在样式与导出中的体现、旋转圆点与角手柄、复制带外观，图层模块的形状与图片、拖动、滚轮、边手柄、旋转、混合模式、人物之上 / 之下、列表顺序、隐藏、刷新后恢复与删除。

桌面歌词回归：`node tools/verify-lyrics.cjs`，检查 LRC / QRC / YRC 解析、翻译合并、进度计算、卡拉 OK 逐字 `--p` 填充与间奏呼吸点、舞台行、底衬与逐字浮现、演示时钟按切换方式循环各句、字体 / 字重 / 描边 / 对齐 / 时长 / 下一句等控件到达预览、自定义字体、拖动与方向键、导出按颜色画出当前句、客户端载荷（按显示器像素）、自动模式提示、状态校验与持久化。

动态壁纸回归：`node tools/verify-live.cjs`，在页面内录一段 WebM 经文件选择器导入，检查静帧成为壁纸、两块画布与分区的裁切与定位逐项一致、帧持续推进、开关 / 人物优先 / 减少动态效果的退回规则、给客户端的几何方案、刷新后从 IndexedDB 恢复；再用内置人像壁纸合成一段「人物左右走动」的视频，验证逐帧提取：原位像素与补全背景一致（人物被盖住）、悬浮副本画布里有蒙版人物且覆盖静态副本、背景板在人物不经过的位置学到了视频里后来变红的背景而人物身后仍是补全结果、保留原位人物时不遮盖、开关可关可开；最后移除。

模块机制回归：`node tools/verify-modules.cjs`。覆盖示例模块的视图、控件、拖动、键盘、导出像素与持久化，状态校验，运行中注册模块与绘制顺序，处处抛错的模块不影响核心，以及事件、`api`、`storage`。

拖动画面回归：`node tools/verify-drag-motion.cjs`，检查鼠标尚未松开时画面已经更新（含垂直线纯纵向拖动），并验证人物整体变换、关闭联动和导出一致性。
